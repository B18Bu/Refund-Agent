## 管理层结论

### 一句话结论

市场上存在大量「局部竞品」，但公开资料中未发现一个可以直接替代本项目的「订单 + 证据 + 风控 + 舆情 + 人工审批 + 自动退赔」全链路产品。本项目应定位为**电商退款场景的决策编排与审计控制面**，通过标准接口接入风控、OCR、内容安全、舆情和订单系统。

### 推荐采购路径

推荐采用「**自建核心控制面 + 采购可插拔能力组件**」的组合式路线：

- **本系统负责控制：** 金额红线、证据门槛、审批权限、状态机、幂等、审批锁、审计和最终退赔动作授权。
- **风控供应商负责提供信号：** 用户、设备、行为、关系网络、黑灰产和异常模式评分。
- **OCR/内容安全供应商负责处理材料：** 凭证抽取、图片质量、文本风险、图文一致性和内容安全。
- **舆情供应商负责群体信号：** 热点、集中客诉、质量事故和风险趋势。
- **ERP/OMS 或平台接口负责业务事实：** 订单、履约、物流、售后和渠道状态。

### 为什么不建议直接采购单一平台

海外反欺诈平台通常强于支付欺诈、拒付、账户攻击和策略滥用；国内厂商通常强于本地业务风控、内容安全、舆情监测和私有化交付。二者均不应被默认视为：

- 中文退款描述和图片凭证的完整审核系统；
- 可恢复的人工审批状态机；
- 适配国内多电商平台的统一售后工作台；
- 可以直接控制真实资金动作的支付系统。

### 立项必须锁定的原则

1. **宁挂勿错退：** OCR 低置信度、模型超时、非法输出、证据缺失或规则冲突时，默认转人工。
2. **模型只提供信号：** 金额、资损、欺诈、舆情和权限红线由确定性规则控制。
3. **舆情不单独拒赔：** 舆情只用于群体风险、审核优先级和阈值调节，不作为单笔退款真伪的唯一证据。
4. **系统状态不等于支付事实：** `AUTO_REFUNDED` 只能表示决策结果，不能被解释为已经调用真实支付接口。
5. **数据最小化：** 用户投诉、OCR 文本、图片和提示词材料均是不可信输入，不能覆盖系统规则或扩大工具权限。

## 项目需求基线

### 业务场景

目标场景是电商平台在大促、质量事故、物流异常、公共事件或服务故障期间，同时出现大量退款请求。系统需要在保证消费者合理权益的前提下：

- 识别恶意刷单、虚假凭证、重复退款、薅羊毛、团伙套利和异常集中请求；
- 自动处理证据充分、金额较低、风险较低的工单；
- 将高金额、高风险、不确定或异常工单交给人工；
- 让客服主管看到每个 Agent 的执行路径、证据、原因和审批时间线；
- 在并发提交和并发审批时避免重复工单、重复审批和资金风险。

### 输入、输出与责任边界

| 类别 | 典型字段 | 采购验证重点 | 最终责任方 |
| --- | --- | --- | --- |
| 订单事实 | 订单号、金额、商品、履约、发货/签收、物流节点 | 实时性、字段版本、数据一致性、渠道覆盖 | ERP/OMS/平台接口 |
| 用户与行为 | 用户 ID、设备、账号历史、退款频率、关联账号 | 关联网络、黑灰产、原因码、授权链路 | 风控供应商 + 本系统 |
| 退款诉求 | 原因、客服备注、用户描述、时间线 | 分类能力、中文支持、脱敏和保留期 | 本系统 |
| 证据材料 | 破损图、快递单、聊天截图、发票、视频 | OCR、图片质量、图文一致性、低置信度处理 | OCR/内容供应商 + 本系统 |
| 外部信号 | 风控评分、舆情等级、热点事件、商品风险 | 超时、失败、版本、原因码、数据来源 | 外部供应商 |
| 决策输出 | 自动处理、转人工、拒绝、补充材料、审批意见 | 可解释、可回放、状态恢复、审计完整性 | 本系统 |

### 状态机与安全边界

```text
RECEIVED → RUNNING → COMPLETED
                       ├─ AUTO_REFUNDED（决策结果，不代表支付已执行）
                       ├─ APPROVED（人工批准）
                       ├─ REJECTED（拒绝）
                       └─ FAILED（不可恢复失败）
             ↓
          SUSPENDED（人工审批或补充材料）
```

以下情况必须进入 `SUSPENDED` 或 `FAILED`，不能自动放行：

- 金额超过项目确定的自动处理上限；
- OCR 平均置信度低于阈值，或关键字段缺失；
- 风控或舆情服务超时、返回非法结构或版本未知；
- 发现疑似团伙、重复申请、凭证不一致或高风险舆情；
- 审批锁竞争失败、幂等键冲突或数据库条件更新失败。

## 调研方法与证据分级

### 调研范围

- **时间：** 截止 2026 年 9 月 1 日。
- **地域：** 中国、美国、以色列起源厂商、巴西厂商及全球化 SaaS。
- **品类：** 电商反欺诈、退款/退货滥用、拒付保护、业务风控、内容安全、舆情监测、ERP/OMS 和退货体验。
- **目标：** 识别可采购能力、不可替代的自建能力、数据与合规风险、PoC 验收方法和供应商准入门槛。

### 证据等级

| 等级 | 证据 | 允许的结论 |
| --- | --- | --- |
| A | 厂商官网产品页、官方 API/安全文档、合同/PoC 结果 | 可写入公开定位；PoC/合同结果可写入验收项 |
| B | 厂商官方白皮书、案例、公开演讲 | 可作为能力线索，必须 RFI 核验 |
| C | 第三方报告、媒体、客户口碑 | 只能作为线索，不作为采购结论 |
| D | 推测、单一销售口头表述、未提供证据的宣传 | 不得作为准入依据 |

### 判读规则

「高/中/低」表示公开能力与目标系统的**重叠度**，不是厂商实力排名；「需验证」表示资料不足，不代表支持或不支持。所有评分只能在统一样本、统一安全门槛和统一数据条件下比较。

## 市场定义与竞争边界

### 直接竞品与能力标杆

重点解决交易欺诈、拒付、账户攻击、优惠滥用、退款/退货策略滥用或售后欺诈：

- Forter；
- Riskified；
- Signifyd；
- Sift；
- ClearSale。

### 组件型竞品

重点提供风险、支付、内容或数据能力，通常不能替代完整售后工作流：

- 数美科技、同盾、百融智能；
- Stripe Radar、Adyen RevenueProtect；
- OCR、图像安全与内容审核服务。

### 舆情与流程型产品

提供群体风险感知、订单事实或退货体验：

- 蚁坊软件、识微科技；
- 聚水潭、旺店通；
- Loop Returns、Narvar。

### 平台内建能力

淘宝/天猫、京东、拼多多等平台有内建售后与治理能力，但通常不能作为独立 SaaS 采购。它们适合作为用户体验、规则和效率基准，不应直接放入供应商同表排名。

## 重点供应商分析

### 海外直接标杆

#### Forter

| 维度 | 结论 |
| --- | --- |
| 公开定位 | 数字商业场景的信任与智能决策平台，围绕欺诈、账户和交易风险。 |
| 可借鉴能力 | 身份、设备、行为和交易信号汇聚；实时风险结论；策略滥用和账户攻击治理。 |
| 项目交集 | 可作为实时风险决策和策略滥用的标杆。 |
| 主要缺口 | 公开资料不足以证明中文退款描述、图片 OCR、舆情输入、人工审批状态机和中国数据处理。 |
| RFI 重点 | 退款/退货滥用案例、中文证据、多区域数据驻留、原因码、模型版本、SLA 和故障回退。 |

#### Riskified

| 维度 | 结论 |
| --- | --- |
| 公开定位 | 电商风险管理、拒付保护、账户安全和策略保护。 |
| 可借鉴能力 | 订单级风险判断、商业保护模式、退款/退货/优惠等 policy abuse 识别。 |
| 项目交集 | 与退款策略滥用和电商订单风险重叠较高。 |
| 主要缺口 | 不能假设具备中文图片证据、OCR、舆情和国内电商平台集成。 |
| RFI 重点 | 要求用本项目退款案例演示，而非只展示支付拒付指标。 |

#### Signifyd

| 维度 | 结论 |
| --- | --- |
| 公开定位 | Commerce Protection，围绕订单欺诈、拒付和商业保护。 |
| 可借鉴能力 | 订单级风险决策、拒付运营和商业损失控制。 |
| 主要缺口 | 退款描述、图片、OCR 字段是否可作为特征，以及中国本地部署与合规均需验证。 |
| RFI 重点 | 输入字段、原因码、人工审核、数据驻留和服务 SLA。 |

#### Sift

| 维度 | 结论 |
| --- | --- |
| 公开定位 | Fraud Prevention Platform，覆盖支付欺诈、账户防护和滥用识别。 |
| 可借鉴能力 | 跨账号、设备和行为的关联分析；实时评分；账户攻击与业务滥用治理。 |
| 采购定位 | 更适合作为风险 API 或引擎组件，而不是完整售后工作台。 |
| RFI 重点 | 退款策略滥用、事件接口、可解释字段、失败回退和跨境数据安排。 |

#### ClearSale

| 维度 | 结论 |
| --- | --- |
| 公开定位 | 电商反欺诈与拒付保护。 |
| 可借鉴能力 | 自动判定与人工审核协同、欺诈预防和拒付运营。 |
| 主要缺口 | 中国市场交付、中文材料、图片处理和数据驻留需验证。 |
| RFI 重点 | 人工审核方式、支持区域、中文服务、SLA 和数据处理协议。 |

### 中国风控与内容安全候选

#### 数美科技

公开定位同时覆盖内容安全与智能业务风控，与「退款描述 + 图片凭证 + 行为风险」的输入结构较接近。重点验证退款/售后、羊毛党、虚假凭证、营销套利模型，以及私有化部署、数据驻留、图文一致性、模型解释与审计接口。

#### 同盾

公开定位聚焦智能分析、决策和欺诈风险预测。适合评估身份、设备、行为、关联网络、重复申请和团伙风险输入。重点验证电商退款训练样本、原因码、特征解释、API 集成、模型版本和人工反馈闭环。

#### 百融智能

公开定位为数据智能服务，可作为数据与风险决策候选。不得从「数据智能」直接推断其具备电商退款专用能力，必须核验数据来源、授权链路、个人信息边界、留存期限和可解释性。

### 中国舆情与电商流程候选

#### 蚁坊软件、识微科技

适合作为群体性客诉和事件感知层：发现商品质量事故、物流异常、热点扩散和集中投诉，帮助调整人工队列优先级、暂缓某类自动处理或通知运营排查。不得仅凭负面舆情拒绝单笔退款。

#### 聚水潭、旺店通

适合作为订单、履约、物流、仓储、渠道和售后事实来源。它们不是反欺诈系统，不能替代风险判断、证据审核、人工审批或审计控制面。

## 能力差距与自建边界

| 能力域 | 外部产品常见优势 | 外部产品常见不足 | 本系统应否自建 |
| --- | --- | --- | --- |
| 用户/设备/行为风险 | 海外和国内风控产品均较成熟 | 数据覆盖、跨境、解释性和费用差异大 | 不自建底层数据；保留适配层和策略编排 |
| 退款/退货滥用 | 海外直接标杆较强 | 中国平台和售后政策适配需验证 | 自建场景规则与标签体系，外部评分可插拔 |
| OCR 与凭证 | 内容安全/OCR 厂商可提供组件 | 低置信度、图文一致性和业务语境需结合 | 自建阈值、证据门槛、回退和审计 |
| 舆情感知 | 国内舆情产品覆盖广 | 不能证明单笔退款真伪 | 采购聚合信号；自建使用规则 |
| 人工审核与状态机 | 部分产品有运营后台 | 难与既有权限、锁、幂等和 LangGraph 结合 | 必须自建 |
| 金额与资损控制 | 供应商可返回风险评分 | 黑箱评分不能成为支付授权 | 必须自建确定性规则 |
| 审计与解释 | 部分产品提供原因码 | 字段粒度、版本和保存期限不一致 | 必须自建统一审计模型 |
| 实际退赔动作 | 平台/支付方各自负责 | 供应商与资金系统边界复杂 | 必须隔离，由受控支付服务执行 |

**核心判断：** 外部供应商解决「我看到什么风险」，本项目解决「在什么规则下允许什么动作」。采购合同不应让供应商绕过本系统直接执行真实退款。

## 采购方案与推荐架构

### 方案比较

| 评价维度 | 方案 A：单一海外平台 | 方案 B：组合式（推荐） | 方案 C：完全自建 |
| --- | --- | --- | --- |
| 上线速度 | 快 | 中 | 慢 |
| 中国电商与中文证据 | 需验证 | 较强 | 可定制 |
| 退款工作流控制力 | 中 | 高 | 高 |
| 供应商锁定风险 | 高 | 中 | 低 |
| 初期投入 | 采购费为主 | 集成费 + 组件费 | 研发与数据建设 |
| 长期运营 | 依赖供应商 | 多供应商治理 | 自有算法和运营团队 |
| 适用场景 | 跨境、拒付优先 | 中国渠道、强审计要求 | 大规模且已有成熟风控团队 |

### 推荐架构

```text
订单/ERP/OMS ─┐
退款描述/图片 ─┼─> 证据抽取：OCR / 内容安全 ─┐
用户/设备行为 ─┼─> 风控服务：评分 / 原因码 ──┼─> 决策编排与审计控制面
舆情聚合信号 ─┘                               │       ├─ 低风险且证据完整：自动处理
                                                │       ├─ 不确定/异常：挂起转人工
                                                │       └─ 命中红线：拒绝或补充材料
                                                └─ 审批、幂等、审批锁、状态恢复、审计
```

### 控制面职责

- 订单和金额规则；
- OCR 置信度与证据完整性门槛；
- 风控/舆情结果的超时、失败和非法输出处理；
- 人工队列、角色权限、审批锁和二次确认；
- `RUNNING → SUSPENDED → COMPLETED` 状态恢复；
- 幂等键、数据库条件更新和审计日志；
- 与真实支付/退赔服务的隔离和授权。

### 能力面职责

外部厂商通过标准 API 或事件接口提供可替换能力。单个工具失败不得取消其他并行结果；失败后系统必须使用保守默认值并转人工。

## 供应商准入与加权评分

### 一票否决项

以下任一项不满足，不进入商务比价：

- 无法提供数据处理地点、子处理商和个人信息处理说明；
- 无法在异常、超时或模型非法输出时保守回退；
- 无法提供最小限度的原因码、版本号和审计日志；
- 要求把原始图片、投诉文本或敏感数据用于未约定的训练；
- 无法支持租户隔离、访问控制、密钥轮换和数据删除；
- 不能接受本系统掌控最终退赔动作和审批权限；
- 不能以书面方式承诺接口 SLA、限流、故障通知和退出导出机制。

### 建议加权评分

总分 100 分，先过一票否决，再进行评分。每项按「证据充分度 × 场景得分」计算，不能只听销售演示。

| 维度 | 权重 | 评分要点 |
| --- | ---: | --- |
| 退款/退货滥用适配 | 20 | 真实案例、样本效果、重复退款、团伙与策略套利 |
| 风控与特征能力 | 15 | 用户、设备、行为、关系网络、规则和原因码 |
| 多模态证据 | 15 | OCR、图片质量、图文一致性、篡改和低置信度处理 |
| 可解释与审计 | 10 | 特征摘要、模型/规则版本、决策链和导出 |
| 集成与可靠性 | 10 | API、Webhook、幂等、限流、超时、SLA、回退 |
| 中国合规与安全 | 15 | 数据驻留、个人信息、跨境、子处理商、认证 |
| 交付与运营 | 5 | 实施团队、中文支持、监控、培训、响应时间 |
| 商业条款 | 10 | 计费透明度、容量阶梯、保障边界、退出与数据可携带 |

### 评分等级

| 分数 | 采购建议 |
| ---: | --- |
| 85–100 | 可进入商务谈判和生产前安全评审 |
| 70–84 | 可进入二轮 PoC；必须关闭关键缺口 |
| 60–69 | 仅作为备选或组件，不建议承担自动放行 |
| 0–59 | 不进入本项目采购范围 |

| RFI-12 | 性能 | QPS、P95/P99、限流、突发容量和降级策略是多少？ | 压测报告、SLA |

| RFI-14 | 商务 | 按订单、评分、调用量、保障金额还是年费计价？ | 报价单、阶梯价格、超额费 |
| RFI-15 | 退出机制 | 终止后多久导出数据、删除副本和关闭密钥？ | 退出流程、合同条款 |

## PoC 验收方案

### PoC 目标

验证候选供应商能否在不降低安全门槛的前提下，减少人工审核量、提高风险识别质量、提供可解释证据，并在服务异常时安全降级。

### 样本集设计

建议使用脱敏历史工单与合成样本混合，至少包含：

1. 正常退款与真实破损、少件、错发；
2. 证据充分但金额不同的工单；
3. 图片模糊、OCR 低置信度、字段缺失；
4. 重复退款、虚假描述、图文不一致；
5. 多账号、多设备、集中下单或疑似团伙；
6. 大促、物流事故、商品质量事故导致的集中客诉；
7. 风控超时、舆情不可用、模型返回非法结构；
8. 审批并发、重复提交和幂等键重放。

历史人工结论不能直接视为真值，应由业务、风控、售后共同复核标签。

### 测试分组

| 组别 | 目的 | 必测结果 |
| --- | --- | --- |
| 正常低风险 | 验证安全自动处理 | 正确放行率、证据完整率、P95 时延 |
| 高金额 | 验证金额红线 | 100% 转人工或拒绝 |
| 高风险行为 | 验证欺诈与团伙 | 命中原因、关联证据、人工队列优先级 |
| 低质量证据 | 验证 OCR/图片降级 | 100% 不自动放行 |
| 集中客诉 | 验证舆情用途 | 调整队列/阈值，不直接拒赔 |
| 依赖异常 | 验证容错 | 其他结果保留、保守回退、可审计 |
| 并发与重放 | 验证工程防御 | 不重复建单、不重复审批、不覆盖状态 |

### 指标定义

| 指标 | 定义 | 采购关注点 |
| --- | --- | --- |
| 安全自动处理率 | 在全部硬规则满足的样本中，安全自动处理的比例 | 必须与误放行一起看 |
| 误放行率 | 实际高风险/不应退款样本被自动处理的比例 | 属于关键资损指标 |
| 误拦截率 | 真实合理退款被拒绝或不必要转人工的比例 | 影响消费者体验和人工成本 |
| 原因码完整率 | 每条决策包含可复核原因码和版本的比例 | 建议生产门槛为 100% |
| 人工节省率 | 相比基线规则，人工审核量下降比例 | 必须在相同安全门槛下计算 |
| P95/P99 时延 | 从请求到可用决策的分位数延迟 | 与峰值流量、超时策略同时验收 |
| 故障回退成功率 | 依赖异常时进入安全状态的比例 | 不允许静默放行 |

### 通过标准

- 命中金额、OCR、欺诈或安全红线的样本，自动放行率必须为 0%。
- 模型超时、非法输出和证据低置信度必须保守转人工。
- 每条自动决定必须关联规则/模型版本、原因码和输入摘要。
- 候选产品在同一数据集和同一安全阈值下，能证明人工量下降或审核时长改善。
- PoC 不连接真实支付接口，使用独立测试租户、最小权限和脱敏数据。

## 安全、合规与合同条款

### 数据处理要求

- 明确订单、用户、图片、OCR 文本、投诉内容、设备标识和日志的字段级分类。
- 明确数据存储地、处理地、备份地、子处理商和跨境路径。
- 原始图片与投诉文本按最小化原则传输，不得默认用于供应商训练。
- 明确保留期限、删除 SLA、备份副本删除、导出格式和终止后回收证明。
- 脱敏、加密、访问审计和密钥轮换必须有可验证证据。

### 模型与算法要求

- 返回模型版本、规则版本、原因码、时间戳和输入摘要。
- 说明训练数据来源、适用地域、偏差监控和人工反馈机制。
- 支持版本回滚、灰度、A/B 标记和变更通知。
- 不得使用不可审计的黑箱输出直接授予自动退赔权限。

### 服务可靠性要求

- 约定可用性、P95/P99 时延、峰值 QPS、限流和突发容量。
- 约定超时、重试、熔断、降级、故障通知和恢复时间。
- 支持请求幂等、响应签名、事件回放和审计查询。
- 供应商故障时，本系统必须能够转人工，不得阻塞主事件循环或改变审批结果。

### 商务与退出要求

- 计费单位必须可复算，区分有效调用、重试、失败请求、人工审核和保障金额。
- 约定容量阶梯、超额价格、最低消费、价格调整和汇率风险。
- 明确误判、拒付、服务中断、数据泄露和第三方子处理商责任。
- 约定终止后的数据导出、删除、迁移支持和密钥关闭时间。

## 实施治理与运营指标

### 角色分工

| 角色 | 主要责任 |
| --- | --- |
| 业务负责人 | 定义退款政策、品类差异和消费者体验目标 |
| 客服运营 | 定义队列、人工审核 SOP、升级和复核机制 |
| 风控/算法 | 定义标签、阈值、特征、误伤与资损监控 |
| 技术架构 | 定义 API、状态机、幂等、锁、可观测和容灾 |
| 法务/隐私 | 审核数据处理、跨境、子处理商和合同责任 |
| 采购/财务 | 供应商比价、计费模型、SLA 和退出条款 |
| 内审/安全 | 抽检决策链、权限、日志、变更和异常处理 |

### 生产运营看板

建议至少监控：

- 自动处理率、人工转入率、拒绝率、失败率；
- 误放行、误拦截、复议率、人工审核耗时；
- 按金额、品类、渠道、用户层级和事件窗口拆分的资损指标；
- OCR 低置信度率、风控超时率、舆情不可用率；
- 幂等冲突、审批锁冲突、重复请求和状态异常；
- 供应商可用性、P95/P99、限流、重试和版本变更。

### 灰度策略

1. **影子模式：** 供应商只返回评分，不影响业务决定。
2. **建议模式：** 风险结论展示给客服，全部人工决定。
3. **受控自动模式：** 只对小额、低风险、证据完整工单自动处理。
4. **扩大范围：** 通过月度复盘、抽检和资损门槛后逐步扩大。

## 风险台账与决策门

| 风险编号 | 风险 | 影响 | 预防/缓解措施 | 责任角色 | 决策门 |
| --- | --- | --- | --- | --- | --- |
| R-01 | 把支付反欺诈误当退款风控 | 高 | RFI 强制要求退款案例与样本演示 | 业务/风控 | 未证明不进入自动放行 |
| R-02 | 外部评分黑箱导致误退 | 高 | 原因码、版本、硬规则和人工回退 | 风控/技术 | 解释字段不完整即否决 |
| R-03 | OCR 或图片误识别 | 高 | 置信度阈值、图文一致性、低置信度转人工 | 算法/客服 | 低置信度自动放行=0 |
| R-04 | 舆情误伤合理退款 | 高 | 舆情仅用于群体信号和队列优先级 | 业务/舆情 | 不得单独拒赔 |
| R-05 | 数据跨境或训练用途不清 | 高 | DPA、数据驻留、删除证明、禁止未授权训练 | 法务/安全 | 合规材料不全即否决 |
| R-06 | 供应商不可用阻塞退款 | 中高 | 超时、熔断、保守回退和人工通道 | 技术 | 故障演练不通过不得上线 |
| R-07 | 并发重复审批/重复退款 | 高 | Redis 幂等键、随机 token 锁、DB 条件更新 | 技术 | 并发 PoC 不通过不得上线 |
| R-08 | 供应商锁定与迁移困难 | 中 | 标准 API、字段归一化、数据可携带和退出条款 | 架构/采购 | 无退出条款不签约 |

### 关键决策门

- **准入门：** 一票否决项全部通过。
- **PoC 门：** 安全门槛、回退、解释、数据隔离和并发测试通过。
- **灰度门：** 影子/建议模式运行稳定，抽检无资损红线。
- **生产门：** 业务、风控、技术、法务、采购和安全联合签字。

## 结论与下一步

### 最终建议

本项目最适合走「组合式采购 + 自建决策编排」路线。采购重点不应是寻找一个宣传口径上“什么都能做”的平台，而应是验证每家供应商在某一能力域是否可靠、可解释、可合规、可替换，并由本系统将这些能力编排成受控的退款决策闭环。

### 建议的 6 周调研与采购节奏

| 周期 | 工作 | 产出 | 责任方 |
| --- | --- | --- | --- |
| 第 1 周 | 业务访谈、样本盘点、规则与合规边界确认 | 需求基线、样本标签方案 | 业务/风控/法务 |
| 第 2 周 | 向候选厂商发出 RFI | RFI 回复与供应商短名单 | 采购/技术 |
| 第 3 周 | 安全、数据、集成预审 | 准入审查表、风险台账 | 安全/法务/架构 |
| 第 4 周 | 两家候选进入隔离 PoC | 统一测试结果、问题清单 | 技术/风控/供应商 |
| 第 5 周 | 商务、SLA、退出与数据条款谈判 | 评分表、报价比较、合同附件 | 采购/法务/财务 |
| 第 6 周 | 影子模式与灰度计划评审 | 上线门禁、运营看板、回滚方案 | 联合评审组 |
