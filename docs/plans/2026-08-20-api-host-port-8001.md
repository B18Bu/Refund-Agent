# API 宿主端口切换至 8001 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 将 Docker Compose 的 API 宿主机访问端口从 8000 切换至 8001，同时保持容器内 API 监听和服务间通信不变。

**架构：** 仅更新 `api` 服务的 Docker 端口发布规则，使宿主机 `8001` 映射到容器 `8000`。Uvicorn 和前端 Nginx 均继续使用容器内 `8000`，避免改变 Docker 网络内的服务发现与代理目标。

**技术栈：** Docker Compose、FastAPI/Uvicorn、Nginx。

### 任务 1：更新 Compose 的 API 宿主机端口发布规则

**文件：**
- 修改：`docker-compose.yml:60-61`
- 测试：运行中 Compose 服务的端口发布与健康检查。

- [ ] **步骤 1：确认当前 API 服务端口配置**

运行：

```powershell
docker compose config
```

预期：`api` 服务当前的 `ports` 包含目标改动前的端口发布规则 `8000:8000`。

- [ ] **步骤 2：更新最小配置**

将 `docker-compose.yml` 的 API 端口发布规则替换为：

```yaml
    ports:
      - "8001:8000"
```

不要修改 `command: uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4`，也不要修改前端 Nginx 的 `proxy_pass http://api:8000`。

- [ ] **步骤 3：验证 Compose 配置可解析**

运行：

```powershell
docker compose config --quiet
```

预期：命令退出码为 0，且没有 Compose 配置错误。

- [ ] **步骤 4：重建 API 容器以应用端口映射**

运行：

```powershell
docker compose up -d --no-deps --force-recreate api
```

预期：仅 API 服务被重新创建并进入 `Up` 状态。

- [ ] **步骤 5：验证对外映射与服务健康状态**

运行：

```powershell
docker compose ps api
Invoke-WebRequest http://localhost:8001/healthz -UseBasicParsing
```

预期：`docker compose ps api` 显示 `0.0.0.0:8001->8000/tcp`；健康检查返回 HTTP 200。

- [ ] **步骤 6：验证旧宿主机端口未继续提供 API**

运行：

```powershell
Test-NetConnection localhost -Port 8000 -InformationLevel Quiet
```

预期：返回 `False`，证明 API 不再发布至宿主机 8000；容器网络内的 `api:8000` 不受该检查影响。

- [ ] **步骤 7：检查改动范围**

运行：

```powershell
git diff -- docker-compose.yml docs/superpowers/specs/2026-08-20-api-host-port-8001-design.md docs/superpowers/plans/2026-08-20-api-host-port-8001.md
```

预期：配置改动仅为 API 宿主机映射 `8001:8000`，新增文档与本计划；不包含无关文件。
