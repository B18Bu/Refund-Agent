# 角色化退款控制台设计规格

日期：2026-08-19
状态：已完成头脑风暴，待用户审查

## 1. 背景与目标

当前系统包含退款工单工作台和实时大屏，但日常处理、主管待办和系统流程说明的职责边界不够清晰。本次设计将登录后的页面统一为角色化应用外壳，并区分退款工作台、实时监控和退款流程总览。

目标：

- 为客服和主管提供不同的导航与默认入口；
- 让主管优先看到异常和待人工审批订单；
- 让客服只看到自己创建的退款申请；
- 保留自动更新，并对新增待办和异常进行明显提醒；
- 用独立流程说明页帮助新用户理解退款决策链路。

非目标：

- 不新增工单分配、组织架构或复杂运营分析；
- 流程总览不负责展示单个订单的实时节点；
- 不在本次设计中改变后端退款决策规则。

## 2. 角色与权限

### 客服

菜单：

- 退款工作台
- 我的申请
- 退款流程总览

默认进入“我的申请”。客服可以创建退款申请、查看自己创建的工单及详情，但不可查看其他客服工单，也不可审批。

### 主管

菜单：

- 实时监控（异常数量徽标）
- 退款工作台
- 待人工审批（待审批数量徽标）
- 退款流程总览
- 数据大屏

默认进入“实时监控”。主管可以查看全部工单并审批待人工处理订单。

权限必须由前后端共同保证：前端根据角色渲染菜单和默认路由；后端列表和详情接口按当前用户角色过滤工单，客服只能访问 `Ticket.user_id == current_user.id` 的记录，主管可以访问全部记录。详情接口同样执行过滤，不能只依赖前端隐藏。

## 3. 统一应用外壳

登录后页面统一使用 `AppShell`，包含：

- 固定左侧导航栏：系统标识、角色化菜单、动态徽标；
- 顶部栏：当前角色、手动刷新、退出登录；
- 主内容区：当前页面内容；
- 响应式行为：窄屏时导航可折叠，内容区不发生横向溢出。

建议的页面路由：

- `/`：按角色重定向，主管到 `/monitor`，客服到 `/my-tickets`；
- `/workspace`：退款工作台；
- `/my-tickets`：客服自己的申请列表；
- `/monitor`：主管实时监控；
- `/process`：标准退款流程说明；
- `/screen`：主管数据大屏；
- `/ticket/:id`：工单详情，后端再次校验访问权限。

## 4. 主管实时监控

监控页采用待处理优先布局，首屏包含：

1. 页面标题、自动更新状态、最近更新时间、手动刷新按钮；
2. 统计卡片：异常订单、待人工审批、正在处理、今日退款金额；
3. “需要优先处理”列表：异常和待审批订单，按紧急程度排列，支持直接进入详情或审批；
4. 当前流程状态概览：提交申请、OCR 识别、风险分析、舆情分析、金额决策等阶段的数量。

状态颜色：

- 异常/失败：红色；
- 待审批：橙色；
- 处理中：蓝色；
- 已完成：绿色。

交互规则：

- 页面自动刷新；
- 新增异常或待审批订单时，更新统计、左侧徽标并显示一次中文提示；
- SSE 可用时使用 SSE，断线后使用现有轮询降级机制，并明确显示“正在重连”；
- 无待办时显示“当前没有需要立即处理的订单”；
- 每条待办订单可跳转 `/ticket/:id`。

## 5. 退款工作台与客服申请

工作台负责创建、查询和进入工单详情，不承担全局流程解释。客服的申请列表使用后端过滤后的数据，仅展示自己创建的工单。主管工作台展示全部工单。

沿用现有建单能力：金额输入、最多三张凭证图片、幂等请求、提交成功提示、订单行点击进入详情。工作台保留状态、结果、欺诈分、舆情和错误信息等已有字段，但使用统一外壳和角色化文案。

## 6. 退款流程总览

流程总览是面向新用户的静态说明页，仅解释标准链路：

`提交申请 → 凭证 OCR → 风险分析 → 舆情分析 → 金额决策 → 自动退赔 / 人工审批 / 处理失败`

页面使用横向步骤图或窄屏可滚动步骤列表，每个步骤包含名称、作用和可能结果。该页不展示单个订单当前位置，也不替代实时监控。

## 7. 数据更新与提醒

复用当前前端已有的定时刷新和后端 SSE 能力。页面需要区分：

- 首次加载中；
- 已连接并自动更新；
- 连接中断、正在轮询降级；
- 请求失败。

不得在数据请求失败时继续显示“自动更新中”。异常提醒只在检测到新增异常或待审批数量增加时提示，避免每次刷新重复弹窗。

## 8. 错误与空状态

- 未登录或 token 失效：清除 token 并跳转登录页；
- 客服访问无权限工单：后端返回 404 或 403，前端显示中文提示并返回自己的申请列表；
- 列表加载失败：保留页面结构，显示可重试错误状态；
- 没有订单：显示空状态和“新建退款申请”入口；
- 监控无待办：显示无待办说明，不使用空白页面。

## 9. 测试与验收标准

### 后端

- 客服列表只返回自己的工单；
- 主管列表返回全部工单；
- 客服无法通过详情接口读取其他客服的工单；
- 主管仍可读取详情并审批；
- 原有建单幂等、审批和 SSE 测试继续通过。

### 前端

- 不同角色看到正确菜单；
- 主管默认进入 `/monitor`，客服默认进入 `/my-tickets`；
- 监控统计和导航徽标随数据刷新变化；
- 新增异常/待审批订单只提示一次；
- 失败、断线、空数据状态显示正确；
- 页面可跳转工作台、流程总览和工单详情；
- 窄屏下导航可折叠且内容无横向溢出。

## 10. 视觉方向

采用专业、克制的运营后台风格：浅色内容区、深色左侧导航、红/橙/蓝/绿状态色，仅用于表达业务状态。避免将监控页设计成高饱和大屏；实时监控优先使用可执行的统计卡片和待办列表，数据大屏继续保留为独立入口。
