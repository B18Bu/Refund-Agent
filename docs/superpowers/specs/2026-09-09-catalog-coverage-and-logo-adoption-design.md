# 商品目录覆盖与品牌标识接入设计

## 目标

提升商城中“手机专区”和“外设专区”的有效商品覆盖，并将既有「确认路径」Logo 接入顾客与运营端的品牌位置。

本设计不改变订单、支付模拟、退款决策、JWT/RBAC、Redis 幂等或审批锁行为。

## 当前问题

当前公开目录总量可以满足浏览，但商品没有持久化业务品类。顾客端以名称关键词过滤“手机”“耳机”等，导致不含该文字的手机型号无法进入手机专区，生活类商品也会稀释来源目录。Logo 已是静态资产，两个应用壳仍使用文字或临时字符标识。

## 数据设计与兼容

在 `products` 表新增非空、受限长度的 `category` 字段，值域固定为：`PHONE`、`PERIPHERAL`、`OTHER`。

- 使用显式 SQL 迁移：先以 `OTHER` 默认值回填已有行，再设为 `NOT NULL`，为 `category` 创建索引；禁止依赖 `create_all` 修改已有数据库。
- `Product`、`ProductDTO`、`ProductOut` 与前端 `Product` 类型增加同名字段。
- 已有商品、购物车和订单快照保持原值；订单继续读取已保存的商品快照与服务端价格，绝不因目录分类重写历史订单。

## 采集与分类

分类由确定性代码产生，不调用 LLM：

1. 适配器优先读取品牌官方响应提供的分类名称。
2. 代码将官方分类和商品名称映射为三个固定值：手机相关映射到 `PHONE`；耳机、充电、路由、线材、保护配件、输入设备、存储、支架及散热设备映射到 `PERIPHERAL`；其余映射到 `OTHER`。
3. vivo 适配器保留导航分类，不再丢弃 `firstCategory` 信息；小米适配器从固定的官方手机与配件目录入口采集并合并去重。
4. 每个请求地址均由代码中的白名单配置提供；页面响应不能指定来源 URL、品牌或分类规则。

采集失败、解析失败或分类不明均按现有失败语义处理，不发布部分目录，也不在 API 请求链路进行网络抓取。

## 发布门槛与缓存

一个候选快照只有同时满足以下条件才能原子发布：

- `vivo` 和 `xiaomi` 来源均存在，且每个来源至少 20 条有效商品；
- 全部来源合计 `PHONE` 不少于 12 条；
- 全部来源合计 `PERIPHERAL` 不少于 20 条；
- 价格仍覆盖 `≤300`、`301–3000`、`>3000` 三个区间。

失败时记录准确错误码。已有 `READY` 目录继续服务并只更新诊断状态；从未成功过的目录返回现有 `503 CATALOG_NOT_READY`。目录 Worker 在同步与消费者知识库索引之间隔离异常：索引服务不可用必须记录失败，但不得回滚已通过门槛的商品目录发布。

## API 与顾客端

- `GET /api/shop/products` 新增可选 `category` 查询参数，只接受三个固定值；无效值返回 422。
- 商品响应包含 `category`；价格、可售状态、品牌和来源约束保持不变。
- 顾客首页的“手机数码”“耳机配件”导航和快捷分类改为传递 `category=PHONE` 或 `category=PERIPHERAL`，不再以关键词作为专区定义。
- 搜索框仍使用关键词，用于跨品类自由检索；品牌和价格筛选可与品类同时组合。

## Logo 接入

- `CustomerShell` 使用 `brand-logo-horizontal.svg`，替换临时 `M` 标记与重复文字；窄屏只显示 `brand-mark.svg`。
- `AppShell` 使用 `brand-mark-reverse.svg` 与“退赔决策控制台”文字，折叠侧栏只显示图标。
- SVG 使用现有 `frontend/src/assets/brand/` 静态资源，无网络请求，不改变导航标签、路由或权限控制。

## 测试与验收

- 分类映射测试：官方分类优先、关键词回退、未知项为 `OTHER`。
- 目录测试：手机或外设任一门槛不满足时不发布；满足门槛时发布；已有目录在失败后继续可读。
- API 测试：按 `category` 过滤、无效值拒绝、返回分类字段。
- 前端测试：两个专区请求正确的 `category` 参数；顾客与运营壳渲染对应 Logo，并在小屏/折叠状态隐藏字标而保留图标。
- 回归：后端测试、前端相关测试和生产构建通过；不修改退款的确定性决策路径。

## 非目标

- 不引入第三方商品来源、用户提交的商品资料或静态演示商品。
- 不修改生产数据库迁移策略、用户角色或授权协议。
- 不将商品采集、目录分类或 Logo 资产用于真实支付、退款执行或权限表达。
