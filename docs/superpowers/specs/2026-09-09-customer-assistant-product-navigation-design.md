# 智能客服商品详情跳转设计

## 目标

当智能客服识别为商品推荐并检索到商品证据时，回复区域仅显示一个“查看商品信息”按钮。点击按钮后，客户进入排序第一件推荐商品的商城详情页。

## 范围

- 客服推荐证据增加受控的内部 `product_id`。
- 会话接口保留证据顺序，前端使用第一件商品作为唯一跳转目标。
- 推荐回复隐藏模型文本和外部来源链接，仅显示“查看商品信息”按钮。
- 非商品推荐、无商品证据、订单和售后咨询继续显示现有文本回复。

## 数据流

1. 商品检索按既有排序返回 `CustomerCatalogChunk`。
2. 客服服务将每条证据的 `product_id` 与来源地址一同写入会话证据。
3. 前端仅接受正整数商品 ID，并为第一条有效商品证据渲染一个按钮。
4. 点击按钮导航至 `/shop/products/:id`，由既有商品详情页加载并校验可售商品。

## 约束与降级

- 不根据外部 URL 推断商品 ID，避免非受控跳转。
- 不改变 JWT、客户角色校验、会话归属或商品详情页权限逻辑。
- 如果证据缺少有效商品 ID，前端不渲染按钮，继续显示客服文本。
- 商品详情不存在或不可售时，既有详情页错误处理负责反馈。

## 验收

- 推荐会话响应包含排序第一的内部商品 ID。
- 推荐回复仅有一个“查看商品信息”按钮，且不出现外部“查看商品资料”链接。
- 点击按钮跳转到该商品的 `/shop/products/:id` 路由。
- 非推荐回复维持当前消息展示。
- 后端会话与前端组件测试覆盖上述行为。
