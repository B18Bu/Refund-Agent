# 多标签登录与智能客服历史会话设计

## 目标

支持在同一浏览器的不同标签页分别登录顾客、客服和主管账号进行演示；让顾客在智能客服浮窗中通过默认收起的左侧历史栏查看并继续自己的全部历史会话。

## 范围与约束

- 登录 Token 改存储于 `sessionStorage`，一个标签页独立一份。刷新保留，关闭标签页清除。
- 不修改 JWT 签发、角色、RBAC、退款审批、人工接管领取条件更新或 DLP 脱敏策略。
- 历史会话持久化复用现有 `CustomerSupportConversation`、`CustomerSupportMessage` 和 `CustomerSupportCase`，不新增表或数据库迁移。
- 顾客只能读取自己的历史会话；不存在或非归属会话仍返回 `404`。

## 多标签登录

前端定义唯一的会话 Token 读取/写入/清理入口，供 Axios 请求拦截、401 处理、登录页、退出登录和 `getSessionUser` 使用。该入口使用 `sessionStorage` 替代 `localStorage`，确保同源标签页间不会覆盖身份。

## 历史会话侧栏

智能客服浮窗头部左上新增“历史会话”按钮。侧栏默认收起，展开后显示当前顾客全部会话，并以最近活动时间倒序展示最近消息摘要、状态和更新时间。

选择一个会话时，前端读取完整脱敏消息并替换当前对话。没有人工工单或工单未结束的会话允许继续发送消息；`RESOLVED` 会话只读并禁用输入。对人工接管且未结束的会话继续使用现有两秒轮询逻辑。

## API 与数据

在现有消费者客服路由中新增会话列表读取接口，仅允许 `CUSTOMER`。返回会话 ID、状态、最近消息摘要和最近活动时间；会话状态以关联人工工单为准，无人工工单时为 `NO_CASE`。查询以当前 `user_id` 过滤，消息摘要来自该会话最后一条已脱敏消息。

## 错误处理

历史列表加载失败不清空当前对话，显示可重试的轻量错误提示。选择会话失败同样保留当前对话。401 仅清理当前标签页的会话 Token，并跳转该标签页的登录页面。

## 验收

1. 同一浏览器两个标签页可分别登录不同角色，互不覆盖；刷新保留当前标签身份，关闭后不再保留。
2. 顾客可展开历史侧栏，看到且只看到自己的会话，按最近活动倒序。
3. 选择未结束会话可继续提问；已结束会话仅可阅读。
4. 原有转人工、客服领取、消息脱敏和角色限制行为不变。
5. 前后端回归测试与前端生产构建通过。
