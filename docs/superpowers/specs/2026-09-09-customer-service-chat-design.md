# 客服人工答疑与短轮询消息同步设计

## 背景与现状

当前用户端点击“转人工客服”后，会创建 `CustomerSupportCase` 并追加系统提示，但客服账号没有客服答疑页面，用户与客服之间也没有独立的双向消息接口。现有 `CustomerSupportConversation` 与 `CustomerSupportMessage` 已保存用户和智能客服消息，`CustomerSupportCase` 已记录工单状态、分配客服和摘要，可在此基础上扩展。

## 目标

- 客服账号（`cs`）可查看所有 `OPEN`、`IN_PROGRESS` 人工会话，不受 `assigned_to` 限制地浏览待处理列表。
- 客服领取会话后可以查看完整脱敏消息，并发送客服回复。
- 用户端在转人工后可继续看到客服消息，并通过短轮询自动刷新。
- 客服端和用户端均每 2 秒轮询一次，页面离开或会话关闭时停止轮询。
- 保留现有 JWT/RBAC、DLP 脱敏、工单领取和关闭规则；客服不能读取其他敏感原文或修改退款审批结果。

## 非目标

- 本轮不引入 WebSocket、推送网关、消息队列或新的外部服务。
- 本轮不增加客服分配算法；客服可从待处理列表领取，数据库条件更新保证并发下只有一个客服领取成功。
- 本轮不改变现有订单、退赔审批和智能推荐逻辑。

## 用户端体验

用户在智能客服浮窗点击“转人工客服”后：

1. 客户端调用现有升级接口，展示“已转人工，等待客服接入”。
2. 浮窗继续展示原有对话，并开始请求该会话的消息列表。
3. 新的客服消息以“人工客服”身份显示；用户发送新问题继续追加到同一会话。
4. 会话被客服关闭后停止轮询并显示“本次人工服务已结束”。

## 客服端体验

新增客服答疑页面，挂载在客服账号首页或订单中心旁的导航入口：

- 左侧会话列表：显示客户标识、工单状态、摘要、更新时间和未读提示；默认加载 `OPEN`、`IN_PROGRESS` 会话。
- 右侧消息区：显示脱敏后的用户、智能客服和人工客服消息，按时间升序排列。
- 操作区：`OPEN` 会话提供“领取会话”；领取成功后显示输入框和“发送回复”；`IN_PROGRESS` 且由当前客服领取的会话提供“结束会话”。
- 其他客服已领取的会话可读但不可发送，避免越权回复。
- 页面以 2 秒短轮询刷新会话列表和当前会话消息；请求失败显示非阻塞错误提示，下一轮继续重试。

## 后端接口

在 `/api/customer-support` 下增加：

- `GET /cases/{case_id}/messages`：客服角色读取指定人工会话消息；仅允许 `CS/SV`，返回消息 ID、发送方、脱敏内容、证据和创建时间。
- `POST /cases/{case_id}/messages`：当前已领取客服发送回复；仅允许 `CS/SV`，要求工单为 `IN_PROGRESS` 且 `assigned_to` 等于当前用户。请求内容先经过 `DLP.mask`，再写入 `CustomerSupportMessage(sender="AGENT")`。
- `GET /conversations/{conversation_id}/messages`：普通用户读取自己的会话消息；仅允许会话所属用户。
- `POST /conversations/{conversation_id}/messages`：扩展现有用户消息接口，保留智能客服自动回复；人工接入后仍写入 `CUSTOMER` 消息并返回智能客服或系统消息。

已有 `POST /cases/{case_id}/assign` 与 `POST /cases/{case_id}/resolve` 保持不变。所有新增查询必须按会话所属关系和角色校验，不能通过路径 ID 访问他人会话。

## 数据与状态

继续使用 `CustomerSupportMessage`，不新增数据库字段：

- `CUSTOMER`：用户消息。
- `ASSISTANT`：智能客服消息。
- `AGENT`：人工客服消息。
- `SYSTEM`：系统状态消息。

人工客服回复不保存未脱敏原文；`evidence` 默认为空对象。会话消息按 `id` 递增返回，前端以最后已知 ID 去重，避免短轮询重复渲染。

## 错误处理与并发

- 未领取会话发送回复返回 `409`。
- 非法会话、非所属用户或不具备客服角色返回 `404/403`，不泄露会话存在性以外的信息。
- 领取使用现有条件更新；并发失败在客服端显示“会话已被其他客服领取”，并刷新列表。
- 轮询请求超时或网络失败不清空已有消息，仅显示轻量错误状态。

## 验收标准

- 用户转人工后，客服账号能在答疑页面看到该会话及用户问题。
- 客服领取并发送回复后，用户端最多 2 秒内看到“人工客服”消息。
- 用户继续发送消息后，客服端最多 2 秒内看到新消息。
- 未领取或非当前客服领取的会话不能发送回复。
- 客服关闭会话后，双方停止轮询并显示结束状态。
- 现有客服工单、智能客服、权限和脱敏测试全部通过；新增接口、状态转换和前端轮询行为有回归测试。
