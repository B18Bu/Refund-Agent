# 结算地址创建与淡蓝商城视觉设计

## 目标

让没有收货地址的客户能在结算页创建地址并继续模拟下单，同时将客户商城的门户、交易流程和服务入口统一为淡蓝色视觉体系。

## 地址创建

- 只使用既有的 `POST /shop/addresses` 接口，不改动 JWT、RBAC、地址隔离、默认地址唯一性或订单模拟支付接口。
- 在结算页“选择收货地址”标题右侧提供“新建收货地址”按钮；地址列表为空时仍展示该按钮。
- 点击后使用 Ant Design Drawer 展开表单，字段为收件人、手机号、省、市、区、详细地址和“设为默认地址”。
- 表单在前端校验必填字段和中国大陆 11 位手机号格式；保存按钮请求中禁用并显示加载状态。
- 创建成功后，将新地址加入本地列表、自动选中，并关闭抽屉；失败时显示服务端错误。新地址创建前，提交订单按钮保持禁用。

## 视觉与布局

- 客户商城采用淡蓝色表面、蓝色交互色、深蓝文字和低饱和边框；不使用红色作为商城主视觉。
- 保留当前“工具栏 / 搜索 / 主导航”和“分类 / 主会场 / 服务”门户层级，不复刻参考图的尺寸、红色导航或促销功能。
- 主会场采用浅蓝渐变和真实目录商品图片；商品、价格、可售状态仍只来自服务端目录。
- 地址区改为蓝白卡片：标题操作区、清晰的已选状态、空状态创建引导；手机端保持单列与可点击的最小交互面积。

## 验收

1. 地址为空时可打开新建抽屉，填写合法数据后向 `/shop/addresses` 提交并自动选中新地址。
2. 新地址被选中后，“提交订单并模拟支付”不再因无地址禁用。
3. 前端地址测试覆盖创建请求和自动选择；商城首页与壳层测试仍通过。
4. 前端构建、商城后端 API 回归测试通过；Docker 前端重建后可通过 `http://localhost` 访问。
